Data Preprocessing

发表于2026-10-08|更新于2026-10-27|Artificial Intelligence
|总字数:7.4k
Cite

Garbage in, garbage out.

真实数据通常不能直接用于训练，常见问题有三类：缺失值与异常值，文本与类别这类非数值类型，以及彼此相差几个数量级的量纲（房价是百万级，房间数是个位数）。多数算法需要数值表示，缺失值、编码与尺度的处理会影响学习结果。这三类问题不处理，模型的拟合结果与评估指标都会跟着偏，后面换什么算法都难以反映真实规律。

预处理是模型的一部分，决定了模型能看见什么：一列缺失超过七成的特征是留着还是删掉，一个无序的港口名是编成 0、1、2 还是拆成三列 0/1，直接改变模型的假设空间。代价有两处。一是每处理一步都要引入一个假设：均值填充与中位数填充的抗极端值能力不同，前者会被极端值拉动，后者更稳；哪种更合适取决于缺失机制与分布，是否成立要回到数据上验证。假设错了，处理得越规整反而离真相越远。二是这些参数（中位数、类别清单、均值与标准差）都必须从训练集估计，再原样套到别的集合上；顺序或作用范围错一步，评估结果就被污染，而这种错误在代码里往往只表现为一个看起来正常的分数。

全章的推进顺序因此是固定的：先划分数据集，把评估用的部分挡在门外。再在训练集上做探索，看清有哪些问题。然后逐类处理重复值、缺失值、异常值、类别编码与量纲。最后用 Pipeline 把这套顺序固化成一条可复用的流水线。下面用泰坦尼克号的生存数据贯穿全文，891 行记录，其中 712 行划作训练集。

先划分数据集

三个子集的分工

用于拟合模型与预处理的统计量应在划分数据后估计，避免验证集或测试集的信息参与拟合。三个子集的用途互不重叠：

子集 比例 用途
训练集 60%-80% 训练模型，学习数据中的规律；这里的 712 行即由此而来
验证集 10%-20% 调整超参数（训练前设定、不由数据学出的量），评估模型在未见过数据上的表现
测试集 10%-20% 模拟真实世界数据，最终评估泛化能力，只在最后用一次

比例不是硬性规定，样本量大时可给训练集更大份额。要点是验证集与测试集各自只承担一件事：调参看验证集，报成绩看测试集。用测试集反复调参，等于把测试集变成第二个验证集，最后的分数不再是泛化能力的估计；这一点在Model-Evaluation里有更完整的讨论。

数据泄露的边界

数据泄露

数据泄露（Data Leakage）指训练阶段用到了预测时根本拿不到的信息。最隐蔽的一种是预处理参数从验证集或测试集上算出来：用全体样本的年龄中位数去填训练集的缺失，这个中位数里已经含有验证集乘客的信息。由此得到一条原则：所有 fit 操作只在训练集上进行，测试集只做 transform。

fit 从数据估计参数，transform 用已有参数改造数据。两者与数据集合绑定：同一次填充，在训练集上要先估计再变换，在验证集与测试集上只做变换。

写成 fit_transform 也不报错

易错点在最后两行：对 X_val 调 fit_transform 语法合法、执行不报错，但中位数换成了验证集上算出的值，评估随之被污染。分数不一定因此升高，方向取决于数据分布；能确定的是这个数字不再代表未见数据上的表现。

交叉验证会把这件事重复很多遍：每一折都相当于重新划分一次，预处理参数必须在每折的训练部分重新 fit，否则验证折的信息提前进了参数。这也是后面用 Pipeline 而不是手写步骤的直接原因。

EDA 能看出什么

EDA（Exploratory Data Analysis，探索性数据分析）是建模之前的系统检查。价值不在看图本身，而在每一层查看都对应一个后续决定；下面按结构、缺失与分布、可视化三层展开。

第一层：结构

.info() 一屏给出列名、非空计数与 dtype，可以回答三类问题。哪些列是文本（dtype 为 object 的 Name、Sex、Ticket、Cabin、Embarked）。哪些列有缺失（Age 只有 569 个非空，Cabin 只有 161 个）。哪些列看似有值却不能直接进模型（Ticket 几乎每行都不同，是取值种类很多的标识，需要先提取信息或编码）。这一层本身不产生处理动作，却定下了后面的清单：object 列是编码的候选，缺失列是清洗的对象，唯一值过多的文本列则要考虑从中提取信息或整列删除。

第二层：缺失与分布

缺失要看两个数：缺多少行、占多大比例。只看行数分不清严重程度，比例才是决策依据：

输出只有三列有缺失：Age 143 行、20.1%，Cabin 551 行、77.4%，Embarked 2 行、0.3%。这三个比例是这份数据上的分档依据：0.3% 删行、20.1% 填充、77.4% 删列。这三个阈值是可检验的候选策略，不是普遍规律。

分布看 describe() 的八个统计量。数值本身不说明问题，彼此对照才有信息：

特征 describe 里的读法 对预处理的含义
Cabin 非空 161，缺失率 77.4% 有效观测只有 161 个；本例可先删列作为候选，与保留并加缺失指示变量的方案对照
Embarked 非空 710，缺失率 0.3% 只有 2 行；本例可先删这两行作为候选，与填充方案对照
Age 非空 569，均值 29.5，中位数 28.0，最小值 0.4 缺失 20.1% 属于中间档，需要填充；均值与中位数接近，取中位数即可
Fare 均值 33.3，标准差 52.4，中位数 15.7，75% 分位 33.4，最大值 512.3 标准差大于均值、最大值远高于 75% 分位，右偏且带极端值，填充与缩放都要挑稳健的统计量
Pclass 取值只有 1、2、3 有序类别；编码方式与是否标准化取决于模型假设，不能只凭有序就禁止当数值处理

第三层：可视化

统计量给的是概要，图形给的是形状。2×3 的子图网格一次看六件事：标签分布、两个连续特征各自的形状、两个类别特征与标签的关系、特征之间的相关性。

图上看出来的几条事实比统计量更直接。票价直方图的第一根柱子约有 395 人，100 之后几乎贴近底部，右偏的形态从图上就能看出。性别与存活的分组柱状图是 male 约 0.19、female 约 0.74，舱位等级是 1 等约 0.64、2 等约 0.44、3 等约 0.24，两个类别特征都与标签有明显关系。相关性热力图上 Survived 与 Fare 是 0.28、与 Pclass 是 -0.35，而 Pclass 与 Fare 之间是 -0.56。两列存在负相关，但可能仍提供不同信息，是否删减需要验证。Survived 与 Age 的相关系数只有 -0.084，接近于零。年龄直方图在 0 到 15 岁一段很矮、20 到 30 岁最高。边际分布本身不能证明 Age 与 Survived 之间存在非线性关系，要按存活分组比较，或交给模型检验。仅凭接近零的相关系数删列，依据不足。

把观察变成策略

每一层观察都要落到一个具体决定上，四层信息对应四类决定：

EDA 看到的信息 对应的预处理决定
dtype 为 object 的列（Sex、Embarked、Cabin 等） 定下编码清单：二分类用 0/1，无序多分类用独热，唯一值过多的列先考虑提取信息或删除
缺失数与样本量的比例 按比例分档：0.3% 删行、20.1% 填充、77.4% 删列
均值、中位数、标准差与极值的相对大小 选填充统计量（偏态用中位数）与缩放方法（受极端值影响的要慎用标准化）
直方图形状、分组柱状图、相关系数 判断哪些特征与标签有关系、哪些特征之间重复，决定保留、构造还是删减

每一条都要把观察翻译成参数或动作；EDA 之后列不出这份清单，说明查看没有落到决定上。

数据清洗

清洗面对三类具体的脏数据：重复的行、缺失的值、偏离群体的极端值。处理难度依次上升：重复行只有删与留，缺失值要判断机制，异常值还要判断究竟是不是错误。

重复行与索引同步

重复行不一定是错误：标签不同、业务对象不同、同一用户多次访问都可能产生相同的特征行。判据是先确认业务主键与时间戳。真正容易错的是删除之后 X 与 y 的对齐：

X_train 与 y_train 是两个独立的表，行与行靠索引对应。只删特征表而不同步标签，可能造成长度不一致或位置错配；后者可能不报错，却会破坏样本与标签的对应关系。删除前先在特征表上构造保留掩码，再用同一个掩码筛两张表，两边的行才始终按原索引配对。如果两表当前行顺序一致，也可以同时 reset_index(drop=True) 之后按位置筛选；但 reset_index 只重排行号，修正不了已经错位的样本，错位要先确认行顺序配对再处理。按索引取子集比按位置切片更稳，因为按索引不依赖两表当前的行号恰好一致。

缺失值按比例分档

分档看两个方向。示例采用 5% 与 70% 两个阈值：低于 5% 且可视为随机缺失时删除对应样本行，高于 70% 时删除整列，中间部分进入填充。阈值是可检验的候选规则，不是定律：高缺失列仍可能携带信息，例如缺失与否本身与标签相关，此时保留该列并加一个缺失指示变量更合适。

两个判据作用的对象不同：比例按列算，决定这一列留不留；删行按样本做，只影响含缺失的那几行。同一个数据集里两者可以同时发生，这份数据正好三种情形各有一例：

缺失比例 处理动作 本例中的列与结果
0.3%，低于 5% 删除含缺失的样本行 Embarked 只有 2 行缺失，删掉这 2 行
20.1%，处于中间 保留整列，按类型填充 Age 有 143 行缺失，用中位数 28.0 填充
77.4%，高于 70% 删除整列 Cabin 只有 161 个非空值，整列删除

填充什么值由特征类型决定：数值型用均值或中位数，类别型用众数或显式填充 Unknown 类别。示例中 Fare 的均值 33.3 大于中位数 15.7，Age 的均值 29.5 与中位数 28.0 接近，两列都取中位数。用均值或中位数填充，本身不能证明数据是随机缺失，也不能证明极端值就是错误。

SimpleImputer 本身是估计器，策略里的均值、中位数、众数都要从训练集算出来，所以这两行 fit 之后，验证集与测试集只能用 transform。

异常值的箱线图检测

异常值（Outliers）指显著偏离其他观测值的极端值。箱线图是检测异常值的标准工具，因为图形只由分位数构成。箱体的上下边是 75% 与 25% 分位数，箱内的横线是中位数，两条须向外延伸到一定范围内最远的观测点。落在须外的点单独画出，这些点是异常值的候选。

Fare 的分位数画出来：箱体底边 8.0、箱内 15.7、箱体顶边 33.4，而最大值是 512.3，须外拖着很长一串点。Age 的箱体是 20.0 到 38.0、中位数 28.0，最大值 80，须外只有少量高龄样本。两列的偏离程度完全不同：一列是长尾，一列更接近自然的高龄乘客。

异常值的统计观察与处理

检测给出的不只是名单，还有三层信息。第一层是位置：哪些样本、落在哪个特征上，Fare 的长尾与 Age 的高龄段是两类不同的问题。第二层是程度：512.3 相对于 75% 分位的 33.4 是十五倍，80 岁相对于箱体顶边 38.0 只有两倍出头。倍数本身不能证明哪一个是记录错误、哪一个是真实值，只说明两列偏离群体的幅度不同。第三层是影响范围：Fare 的均值 33.3、标准差 52.4 已经达到均值的 1.6 倍，标准化要用的两个统计量都被极端值改写过。

处理方式取决于这三层判断，没有统一答案：

  • 能解释的极端值保留。头等舱的高价票是真实存在的业务现象，删掉等于抹掉一类乘客；树模型按阈值切分特征，对特征的绝对尺度不敏感，这类值的影响更小，参见Decision-Tree与Ensemble-Learning。
  • 有明显证据表明是录入错误、数量又极少的样本，修正或删除。
  • 想保留样本但压住影响，就做截尾：把超出分位边界的值拉回边界上，样本还在，极端幅度被削平。
  • 分布本身右偏时，用对数变换把长尾压短，让均值与中位数靠近。这一步有个前提要先查：Fare 的最小值是 0.0，对数在 0 处没有定义，这些 0 票价得先单独处理。
  • 无论删还是留，都要回到填充与缩放上确认统计量是否稳健：中位数比均值抗极端值；标准化用的标准差会被抬高，归一化的分母则直接由最大值决定，后者更怕离群点。这与下一节的选择直接相关。
判断的分界线

判断的分界线是能不能在业务上解释这个值，而不是离群体有多远。可解释的极端值保留，让模型决定是否使用；可核实为录入错误的修正或删除；无法核实又解释不了的先保留并记录，不做无依据的删除。

类别特征编码

编码的目的只有一个：把文本映射成数值，让模型能做数学运算。三种编码的差别只有两点：是否保留顺序、是否引入数值大小。这两点决定了哪种特征能用哪种编码。原始的 sex、pclass、embark_town 三列正好各对应一种情况。

三种编码的差别

编码 映射规则 数值大小是否成立 适用场景
序数编码 按等级映射为整数，如低=0、中=1、高=2 顺序成立；间距只在把数值直接加权的模型里被当成等距 特征有明确等级：学历、满意度、舱位等级
独热编码 每个类别单独一列，命中为 1，其余为 0 不成立，各列之间没有大小关系 无序分类：颜色、城市、登船港口
标签编码 直接映射为 0、1、2，顺序由编码器的排列决定 不成立，但被强行引入 目标变量的整数编码；二分类特征映射为 0/1；无序多分类输入不应使用

序数编码

序数编码（Ordinal Encoding）把类别映射为整数并严格保留顺序，低、中、高对应 0、1、2。序数编码只该用在等级本身有意义的列上：舱位等级 1、2、3 是等级，编码成 1、2、3 或 0、1、2 都保留顺序，方向由映射决定；Pclass 数值越大并不代表舱位越好，系数的正负要结合映射读。反过来，如果给颜色编成红=0、绿=1、蓝=2，类别之间本来没有顺序，编码却造出一套没有意义的顺序与间距；线性模型把这一列直接加权时，还会把间距当成等距。

独热编码

独热编码（One-Hot Encoding）把每个类别变成独立的一列，用 0 和 1 表示，从而消除虚假的大小关系。登船港口有三个取值，编码后是三列，每行只有一个 1。代价是维度：默认实现为每个类别各给一列，N 类得到 N 列；只有显式丢一类才得到 N-1 列，被丢的那一列可以由其余列推出。类别很多时矩阵会变稀疏，每行只有一个非零元；这时可以考虑 Embedding 这类稠密表示，也可以先合并稀有类别。是否换成 Embedding 取决于模型与数据规模，矩阵稀疏本身并不强制换一种表示。

标签编码

标签编码（Label Encoding）把类别按顺序映射成 0、1、2，不保证顺序，同时引入数值大小。sklearn 的 LabelEncoder 面向目标变量 y，不用于编码输入特征；二分类输入特征可以用 0/1 映射，两类映射成 0/1 与两列独热携带同样的二分类信息。单列整数编码与独热并不在所有情况下等价：独热的两列各有系数，0/1 单列只有一个系数，训练时若附加限制权重大小的惩罚，两种参数化受到的约束可能不同。把三分类压成一个 0、1、2 的整数列，线性模型在这一列上同样只有一个系数，等于假定类别之间等距，并不是三个类别各有一个系数。多分类的无序类别不要用标签编码替代独热。树模型按阈值切分，整数顺序会改变可用的切分点，影响比线性模型小，但同样不能说完全不受顺序影响。

encoder 的 fit 同样只碰训练集，学到的类别清单是一项参数。测试集如果出现训练集没有的港口，不带 handle_unknown 时 transform 会直接抛错，这是把 fit 与 transform 分开之后才会遇到的典型问题。

特征构造与量纲统一

编码解决的是能不能进模型，这一步解决的是进去的特征对不对。原始列只是原材料，合并、提取、删减三步把数据列变成有业务含义的特征，随后才轮到把量纲拉到同一尺度。

合并、提取、删减

合并是把分散的信息拼成一个更有解释力的量。SibSp 是同行的兄弟姐妹与配偶数，Parch 是父母与子女数，两列单独看都只说明家庭的一部分。家庭规模按 计算，加 1 是把样本本人算进去；再补一个是否独自出行的标记，取值为 1 表示 FamilySize 等于 1。这个标记可单独表示独自出行与结伴出行的差异，是否与存活有关、能否改善预测，要看数据分析与验证集比较。

提取是从看似无用的文本里挖出结构化信息。姓名列唯一值极多，无法直接编码，但头衔（Mr、Mrs、Master）与性别、婚姻状况相关，可以作为一列类别特征。这种相关性不能当作因果结论，也不能据此断定社会地位；Master 还特指男童。这些是原始列里没有明说、却与存活率相关的变量。

删减要有明确依据。缺失 77.4% 的 Cabin 与格式混乱的 Ticket 是本例的删除候选，先删掉便于得到一个干净的基线。这两列也可能含有可用信息，可以先尝试提取其中有意义的信息，比较之后再决定。任何在预测时拿不到、或会泄露标签的列则应当直接排除：这类信息来得太晚，如果某列在真实预测场景里根本不存在，训练时使用这类列只会让离线分数虚高。三步共同的目标是把杂乱的原始记录整理成模型容易理解的特征。这些规则在训练集与测试集上执行同样的动作，但规则本身（例如头衔到社会地位的映射）只能由训练集归纳，不能拿测试集去补全没见过的头衔。

为什么量纲要统一

同一张表里各特征的取值范围可以差好几个数量级：Age 是 0 到 80，十位数。Fare 是 0 到 100 以上，百位数。SibSp 是 0 到 8，个位数。独热出来的 Embarked_C 只有 0 或 1。尺度大不会自动带来更大的权重，权重由训练决定。尺度的实际作用体现在三处：基于距离的方法让大尺度特征主导距离。梯度下降在不同方向上的曲率差异变大，收敛更慢。正则化对权重的惩罚与特征尺度耦合。是否缩放取决于模型假设，而非特征数值本身。

标准化

标准化（Standardization）使用训练集参数缩放各列，使训练集的非常量列均值为 0、标准差为 1。常量列的标准差为 0，需要单独处理。变换只把中心与尺度对齐，不要求原分布是正态分布，也不保证变换之后数据变成正态分布。变换逐列进行：

归一化

归一化（Normalization）把数据线性变换到一个固定区间，通常是 [0, 1]：

变换后训练集落在 0 到 1 之间。新数据可能超出这个范围，因为边界只来自训练集。常量列的分母为 0，需要单独处理。归一化对异常值比标准化更敏感： 只要被 512.3 这样的值抬高，其余样本就会被压到 0 附近，正常数值之间的差异几乎消失。适用场景是图像数据（像素天然有 0 到 255 的边界），以及模型明确要求输入落在固定区间的场合。神经网络输入也常做归一化，但 sigmoid 只把输出压到 (0, 1)，并不要求输入落在 [0, 1]。

对照项 标准化 归一化
输出范围 无固定区间，均值 0、标准差 1，可以为负 固定为 [0, 1]，不会为负
依赖的统计量 均值与标准差，两者都受异常值影响 最小值与最大值，分母由最大值决定
对异常值的敏感度 中等：极端值抬高标准差，整体仍可用 极高：极端值抬高分母，其余值被压平

手写流程的危险

至此，预处理已经在训练集上估出了一批参数：Age 的中位数 28.0、Fare 的中位数 15.7、Embarked 的类别清单、各列的均值与标准差。手写流程的危险在于这些参数分散在若干次 fit 里，任何一处用错集合都不会报错，只会在分数上表现为一次无法用模型改进解释的变化。更麻烦的是换数据、换折数时要重新检查每一处；检查靠人眼，迟早会漏。

流水线的作用

常见做法是把预处理、特征工程与模型训练封装成流水线（Pipeline），换来三件事：流程可复用、参数归属清楚、便于部署。sklearn 的写法是把列分成两组，各自串一条子流水线，再用 ColumnTransformer 合起来：

流水线把“先划分、再 fit、只 transform”从口头约定变成结构约束。调用 model.fit 时，fit 只在训练集上逐级传递，前面的 imputer 与 scaler 拿到的永远是上游 transform 过的训练数据。调用 predict 或 score 时，中间的预处理只做 transform，最后一级才做预测或评分。交叉验证与网格搜索会在每一折内重新 fit 同一条链，预处理参数只用该折的训练部分估计，这样可以避免验证折的信息进入该折的预处理参数。这并不消灭所有泄露：用全体数据的统计量挑特征、把标签信息带进特征、按测试集分布决定分箱边界，仍然需要靠流程设计逐个排除。这也是把顺序写进代码结构而不是写进注释的理由：预处理的价值不在某一步用了多聪明的统计量，而在每一步的参数归属清楚、顺序固定，换一份新数据能按同一顺序重新执行。

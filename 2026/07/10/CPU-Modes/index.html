CPU 状态与特权级

操作系统要保护系统资源，不能让普通应用程序随意执行影响全局状态的指令。因此 CPU 将指令分为两类：

类型 含义 例子
非特权指令 普通应用程序可以执行 加法、减法、普通数据处理、访问自己的用户空间内存
特权指令 只能由操作系统内核执行 修改 PSW、开关中断、启动 I/O、配置硬件定时器

CPU 也相应分为两种运行状态：

CPU 状态 运行内容 能否执行特权指令 别名
用户态 某个进程或线程的用户代码 不能 目态
内核态 系统调用路径、中断/异常处理、内核线程等内核代码 可以 核心态、管态

CPU 当前处于哪种状态通常由 PSW 中的状态位表示。用户态程序若试图执行特权指令，CPU 会发现权限不匹配，触发异常，转入内核态交给操作系统处理。

内核态不是“操作系统进程”

进程 A 发起系统调用或同步异常时，CPU 通常是在 A 的进程上下文中执行内核代码。当前任务仍是 A，只是 CPU 的特权级、栈和执行代码发生了变化；只有调度器选中 B 并由分派器切换现场后，当前任务才真正改变。

外部中断可以在任意任务运行时到达，处理器会进入中断上下文执行内核代码。

内核线程虽然是真正可调度的执行实体，也只承担特定内核工作，不代表整个操作系统。

时钟

内核维护的时间状态会影响所有进程，可以允许普通程序读取，但不能允许普通程序任意修改。

操作 权限判断
修改系统时间 特权操作
修改时间片余量 特权操作
读取当前时间 用户可以申请
读取进程已经使用的 CPU 时间 用户可以申请
修改用户空间中的普通时间变量 非特权操作

读取时间不一定每次都要通过系统调用切换为内核态。操作系统可以把经过整理的时间数据以只读方式映射到用户空间，例如 Linux 通过 vDSO 加速部分时钟查询。某些处理器还允许用户态读取硬件计数器。

CPU 状态切换

内核态到用户态

内核态到用户态通常由内核控制完成。内核为某个被选中的任务准备好用户现场后，通过体系结构规定的返回指令恢复 PC、栈指针和状态字，使 CPU 回到用户态执行该任务的用户代码。

这个方向是 CPU 从受保护的内核执行路径返回低特权代码，不代表“内核进程把 CPU 交给用户进程”。

用户态到内核态

用户态程序不能直接把 CPU 改成内核态。用户态到内核态必须由硬件事件触发，这个机制就是异常和中断机制。

没有这种机制，应用程序一旦运行，就可能长期占用 CPU，操作系统无法重新获得控制。

异常与中断在状态切换中的作用

异常与中断的完整定义、分类和处理过程见 Exception-And-Interrupt。

它们在操作系统中的作用：

  1. 提供进入内核处理程序的受控入口；事件发生在用户态时，CPU 同时转入内核态，发生在内核态时则保持内核态。
  2. 让操作系统在必要时重新获得 CPU 控制权。
  3. 为系统调用、I/O 完成、时钟调度、错误处理提供统一入口。

异常来自 CPU 内部，通常与当前正在执行的指令有关。异常发生后，CPU 转入内核态，使内核有机会处理当前指令引发的问题或请求。

系统调用使用 trap / 访管指令主动触发自陷；缺页故障、除 0、用户态执行特权指令等也会触发异常。分类细节见 异常。

中断来自 CPU 外部，通常与当前正在执行的指令无关。中断让操作系统可以在用户程序运行期间重新获得 CPU 控制权。

常见中断：

  • 时钟中断：让操作系统周期性获得控制权，可用于计时和调度。
  • I/O 中断：设备完成输入输出后通知 CPU。
  • 不可屏蔽中断：如电源故障等紧急事件。

CPU 通常在一条指令执行结束后检查外部中断。若允许响应，就进入中断响应过程，转到内核中的中断处理程序。

时钟中断和并发

时间片轮转、进程调度等机制需要操作系统周期性取回 CPU。时钟中断提供了这种机会，因此它是多道程序并发运行的重要硬件基础。

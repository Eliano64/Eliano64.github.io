Exception And Interrupt

发表于2026-07-03|更新于2026-08-21|Operating SystemComputer Organization
|总字数:4.1k

CPU 正常执行指令时，可能因为某个事件临时改变控制流，转去执行操作系统内核中的处理程序。这个机制常被统称为“中断机制”，分为以下两种：

  • 异常：由 CPU 内部原因产生，通常和当前正在执行的指令有关。
  • 中断：由 CPU 外部设备产生，通常和当前正在执行的指令无关。

从触发方式看，异常是同步事件，中断是异步事件，它描述的是事件和当前指令流之间的关系：

事件 与当前指令的关系 可预测性 CPU 通常在何处响应
异常 由当前指令的取指、译码或执行直接引起 在相同机器状态下执行同一条指令，通常会在相同位置再次发生 当前指令执行过程中或刚完成时
中断 由定时器、I/O 控制器等外部部件发出，与当前指令内容无直接因果关系 到达时刻取决于外部事件，不能仅由当前指令推断 通常完成当前指令后，在指令边界检查并响应

例如，除零、非法指令和缺页都与正在执行的指令直接相关，属于同步异常；键盘输入、磁盘 I/O 完成和时钟信号可以在程序执行任意指令期间到达，属于异步中断。

中断

中断来自 CPU 外部，通常由 I/O 设备、定时器、外部控制信号等硬件因素触发。它和当前指令本身无关。

类型 信号线 含义 例子
可屏蔽中断 INTR 可以被 CPU 的中断屏蔽位临时禁止响应 普通 I/O 完成中断、定时器中断
不可屏蔽中断 NMI 不能被普通屏蔽机制禁止，优先级高 断电

CPU 在一条指令执行结束后检查是否有外部中断请求。如果允许响应，就保存现场、转入对应的中断处理程序；处理完成后，再恢复现场继续执行原程序。

中断处理程序执行中本身不能调度。如果想要执行某个中断处理程序中执行另一个中断处理程序，则必须使用多重中断技术。

中断隐指令

中断隐指令是 CPU 的硬件 自动完成的一组入口操作，不是程序员在指令系统中显式写出的指令。

中断隐指令的主要任务：

任务 作用
关中断 将中断允许标志置 0，防止保存断点、引出处理程序期间又被新的可屏蔽中断打断
保存断点 保存原程序的 PC，使中断处理完成后能返回原程序
转入内核态 使 CPU 从普通程序的执行状态转入内核态，执行内核代码、访问内核数据结构
引出中断服务程序 根据中断类型号或中断向量找到内核中的服务程序入口，并送入 PC
保存断点和保护现场不是同一件事
概念 保存内容 主要由谁完成
保存断点 PC，即原程序下一步应从哪里继续 中断隐指令(硬件)
保护现场 通用寄存器、状态字、可能被服务程序破坏的运行环境 中断服务程序(软件)

中断的响应与处理过程

中断过程分成两个阶段：

  • 硬件阶段：CPU 响应中断，完成中断隐指令。它暂停现行程序，保存返回所需的断点信息，并把控制权转入内核中的中断入口。
  • 软件阶段：操作系统内核或设备驱动执行中断服务程序。

一次完整的外部中断处理过程是：

  1. 外部设备或定时器发出中断请求。
  2. CPU 在指令边界检查中断允许标志和屏蔽条件；若多个请求同时到达，中断控制器或 CPU 进行判优，选出本次响应的中断源。
  3. 中断控制器向 CPU 提供中断向量号。
  4. CPU 执行中断隐指令：关闭或屏蔽新的可屏蔽中断，保存原程序下一条指令的 PC 和体系结构规定的必要状态，切换到内核态，并根据向量号转入内核中断入口。
  5. 内核公共入口保存可能被处理程序破坏的通用寄存器等现场，再分派到具体中断服务程序。
  6. 中断服务程序完成具体服务，并向设备或中断控制器确认该中断已经处理。
  7. 内核恢复现场，执行中断返回指令，回到原程序下一条指令继续执行。

中断向量表（中断部分）

外部中断被接受后，CPU 必须立即转入对应的内核中断入口。为此，系统提前建立一张按编号索引的中断向量表：启动阶段准备表和公共入口，设备初始化时再建立设备 IRQ、向量号与驱动处理函数之间的关系。

对象 含义
中断向量号 标识本次外部中断，也是向量表索引
向量表项地址 第 个表项在内存中的位置
向量表项 保存中断入口信息及必要控制属性的记录
中断向量 表项给出的中断处理程序入口地址
中断服务程序 入口最终分派到的内核或驱动代码

启动阶段

参与者 负责的内容
处理器体系结构 规定向量号范围、表项格式、查表方式和表基址寄存器
固件 / BIOS 在操作系统尚未运行时提供启动期临时表和基础处理入口
操作系统内核 建立最终向量表，填写默认入口和中断公共入口
中断控制器与驱动 建立设备 IRQ、向量号和具体驱动处理函数之间的运行时关系

机器刚上电时，操作系统还没有运行，但启动过程仍可能需要基本 I/O，固件会先准备启动期临时表和基础入口。

内核接管机器后，不会把固件提供的临时表直接当作最终运行环境，而是建立与自身内核代码、保护机制和驱动框架配套的表。顺序是：

  1. 暂时屏蔽或严格控制外部中断，只保留启动所需的最小执行环境；
  2. 准备中断公共入口和默认处理程序；
  3. 分配向量表，并预先创建体系结构规定数量的表项；
  4. 把处理程序入口信息和控制属性填入相应表项，未使用的表项通常指向默认处理程序或保持为不可用状态；
  5. 通过专用指令把表的基址和界限装入 CPU 的向量表寄存器。

此时 CPU 已经知道最终向量表位于哪里，但外部设备中断仍保持屏蔽，要等中断控制器和驱动准备完成后再开放。

运行准备

最终向量表建立后，还需要把“某个设备发出请求”连接到“某个驱动函数”。以设备驱动初始化为例，过程通常是：

  1. 驱动向内核申请中断资源并登记处理函数；
  2. 内核为设备选择或分配向量号；
  3. 内核在自己的第二级分派表中记录向量号与驱动处理函数的关系；
  4. 内核配置 PIC、APIC 等中断控制器，把设备 IRQ 映射到该向量号；
  5. 所有入口和映射就绪后，内核解除该中断的屏蔽。

硬件向量表的槽位通常在启动时已经按体系结构规定的数量建立。表项可能直接指向某个处理程序，也可能统一指向一组汇编入口，再由内核根据向量号进行第二次分派。共享中断还可能对应一条驱动处理链。

因此，注册新的中断类型或设备处理程序时，系统主要是在分配向量号、更新表项或登记第二级分派关系，并不是到这时才临时创建一个向量表槽位。

运行时查表

中断到达后的向量查找过程是：

  1. 中断控制器向 CPU 提供外部中断向量号；
  2. CPU 从专用寄存器取得向量表基址；
  3. CPU 用向量号定位相应表项，读取处理程序入口和体系结构要求的控制信息。

随后 CPU 完成硬件入口操作，内核公共入口再分派到设备驱动的中断服务程序。

整体流程即：

I/O 中断处理程序

一次典型 I/O 完成中断的处理过程：

  1. 从控制器读出设备状态。
  2. 判断 I/O 是否正常完成。
  3. 若异常，按错误原因处理，例如重试、报告错误、唤醒等待进程并返回错误。
  4. 若正常，读取数据寄存器或确认 DMA/通道已经完成传输。
  5. 更新内核中的 I/O 请求状态和缓冲区状态。
  6. 唤醒等待该 I/O 的进程，或把后续工作交给设备驱动、设备独立性软件继续处理。

单重中断与多重中断

单重中断是在执行中断服务程序时不响应新的中断请求。它流程简单，但高优先级事件可能必须等待当前服务程序结束。

多重中断允许在中断服务程序中重新开中断，使更高优先级的中断源可以打断当前中断服务程序。多重中断需要处理中断优先级、屏蔽字和现场嵌套保存。

什么时候重新开中断？

单重中断在整个服务过程中保持关中断，最后由中断返回指令恢复中断前的 CPU 状态，其中包括中断允许标志。

多重中断先保存当前现场和屏蔽状态，再由软件显式开中断。此后只有未被屏蔽且优先级更高的请求可以打断当前服务程序。

多重中断成立的关键条件：

  • 中断服务程序中提前设置开中断。
  • 高优先级中断源有权打断低优先级中断源。
  • 使用屏蔽字控制哪些中断源可以继续申请。
  • 每次嵌套都要保存对应现场和屏蔽字，返回时逐层恢复。

中断屏蔽字

可屏蔽中断会受中断允许标志 IF 和屏蔽字控制。

  • IF=1：允许响应可屏蔽中断。
  • IF=0：禁止响应可屏蔽中断。
  • 屏蔽字中 1 表示屏蔽某个中断源，0 表示该中断源可以正常申请。

不可屏蔽中断优先级最高，且不受 IF 控制。

屏蔽字的常见判断

屏蔽字中 1 越多表示屏蔽范围越大。
每个中断源对应的屏蔽字至少要能屏蔽自身，否则可能在处理中被同源中断反复打断。

异常

异常来自 CPU 内部，可以分为三类。

类型 英文 含义 处理后返回位置
故障 fault 指令执行过程中发现问题，但通常可以修复 返回引发故障的指令，重新执行；若不可恢复故障则退出当前进程（如除0故障）
自陷 trap 指令正常执行完毕触发，主动转入OS内核，常用于系统调用 返回下一条指令
终止 abort 严重硬件错误，通常无法恢复 程序被迫终止

故障的典型例子是缺页故障：进程访问某个逻辑地址，地址变换时发现目标页不在主存，于是转入缺页处理程序；页面调入后，原访存指令重新执行。

自陷通常是程序主动进入内核的方式。例如用户程序执行系统调用指令，请求操作系统完成文件读写、进程创建等特权操作。

终止表示严重错误。例如无法恢复的机器检查错误，操作系统通常会终止相关进程，甚至导致系统停止。

若异常处理过程中需要等待某事件，则同样进行阻塞然后进程调度。

异常的响应与处理过程

一次异常处理过程是：

  1. CPU 在当前指令执行过程中检测到异常。
  2. CPU 确定异常类型，并找到相应异常处理入口。
  3. CPU 保存必要的断点和程序状态等信息，进入内核态并转入异常处理程序。
  4. 操作系统保存其他必要现场。
  5. 执行具体异常处理；若当前进程需要等待某事件，使其阻塞并调度其他进程。
  6. 若异常可恢复，则恢复现场，并根据异常类型重新执行原指令或从适当位置继续；若不可恢复，则终止当前进程。
没有“多重异常”机制

“多重中断”处理的是多个可以独立到达的外部请求：低优先级中断处理到一半时重新开中断，使已经到达的高优先级请求能够抢占当前处理程序。它依赖中断优先级和屏蔽字。

异常则由正在执行的指令同步产生。异常处理程序自身仍可能因为执行新的指令而再次触发异常。它是处理程序中的新指令产生了新异常，内核必须处理，不能设置优先级和屏蔽。

中断向量表（异常部分）

异常和中断共用一张中断向量表，但两者的向量号来源不同：

  • 异常向量号由处理器体系结构规定，并由 CPU 根据当前指令产生的异常直接确定；
  • 外部中断向量号通常由中断控制器提供，或由内核在设备初始化时建立 IRQ 到向量号的映射。

启动阶段

参与者 负责的内容
处理器体系结构 规定异常类型、向量号、表项格式、查表方式和进入内核时必须保存的状态
固件 / BIOS 在内核接管前提供启动期临时表和最基本的异常入口
操作系统内核 建立最终向量表，安装各类异常入口和默认处理程序

内核建立最终向量表时，先让中断保持屏蔽，再完成以下工作：

  1. 先准备启动早期必须使用的最小异常入口；
  2. 准备各类异常的专用入口和无法归类时使用的默认入口；
  3. 按体系结构规定的数量分配向量表项；
  4. 在相应表项中填写入口地址和控制属性，未使用的表项指向默认处理程序或标为不可用；
  5. 通过专用指令把表的基址和界限装入 CPU 的向量表寄存器。

最终向量表尚未完全建立时，除零、非法指令、缺页等异常仍可能发生，所以启动早期必须先准备最小异常入口。最终表建立后，内核是在已有表项中安装具体入口或更新第二级分派关系，并不是等异常第一次出现时才创建表项。

运行时查表

异常发生后的向量查找过程是：

  1. CPU 根据异常原因在内部得到异常向量号；
  2. CPU 从专用寄存器取得向量表基址；
  3. CPU 用向量号定位表项，读取异常入口和体系结构要求的控制信息；
  4. CPU 保存规定的返回信息并转入内核态；
  5. 内核公共入口再分派到具体异常处理程序。

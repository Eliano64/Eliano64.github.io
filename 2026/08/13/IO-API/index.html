I/O 编程接口

I/O 编程接口是操作系统向程序提供的一组 API，用于访问文件、设备或网络端点等 I/O 对象。它屏蔽控制器寄存器和设备时序，让程序用统一方式表达对硬件的操作。

一个完整的 I/O 编程接口通常由以下内容组成：

组成 回答的问题 例子
操作集合 可以做什么 打开、关闭、读、写、控制
对象标识 操作谁 逻辑设备名、句柄、描述符或通信端点
参数约定 数据与要求怎样表达 缓冲区、长度、读写位置、控制参数
执行语义 请求不能立即完成时怎么办 阻塞、非阻塞、异步完成
结果约定 怎样知道完成或失败 实际传送量、就绪状态、错误码

按设备类型划分

字符设备编程接口

字符设备以字符或字节流为单位传输数据，只能按到达顺序读写，不能像磁盘那样指定某一数据块随机访问。终端、键盘和串口是常见例子。

因此，字符设备编程接口通常具有这些语义：

  • 按字节流顺序读写，不要求块地址；
  • 打开设备时建立一次使用关系，关闭时释放相应状态或设备占用；

块设备编程接口

块设备以固定大小的数据块为基本传输单位，每个块有编号，可以按块随机访问。磁盘和 SSD 是典型块设备。

这些特点使块设备编程接口不仅要说明读写方向和缓冲区，还要指出从哪个块或哪个文件偏移开始、传送多少数据。

操作系统可以在接口下面进行请求合并、调度、缓冲和缓存；一次请求也可能只完成部分数据，调用者需要根据实际完成量继续处理。

网络设备编程接口

网络通信与另一通信端点交换数据。通信可能采用有连接的字节流，也可能采用保留消息边界的数据报。

因此，网络接口需要表达本地与远端地址、通信协议以及发送或接收操作。有连接通信通常先建立连接再收发数据；无连接通信则可在每个数据报中指定对端。网络状态随时可能变化，接口还必须区分暂时无数据、连接关闭、超时和传输错误。

按执行模式划分

阻塞 I/O

阻塞 I/O 在请求暂时不能完成时，让发出请求的线程等待。例如读取终端而尚无输入时，线程会休眠，直到数据到达或发生错误。

  • 优点：控制流程直接；请求返回时通常已经取得数据或得到明确结果。
  • 代价：等待期间该线程不能继续做其他工作；同时处理许多独立 I/O 时，往往需要多个线程。

非阻塞 I/O

非阻塞 I/O 在请求暂时不能完成时立即返回，告诉程序“现在还不能做”。程序可以先处理其他工作，之后重试，或结合就绪通知机制等待多个 I/O 对象中的任意一个就绪。

  • 优点：线程不会被单个慢速 I/O 长时间占住，适合事件循环和大量并发连接。
  • 代价：程序必须处理尚未就绪、部分完成和重复尝试，控制逻辑更复杂；若不断主动查询，还会浪费 CPU 时间。
